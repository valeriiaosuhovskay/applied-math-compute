## 1. Як Python зберігає числа з плаваючою частиною? Скільки байтів?

Python зберігає `float` у форматі **IEEE 754 binary64** ("double precision", тип `double` у мові C). Число розбивається на три частини:

| Частина | Біти |
|---|---|
| знак | 1 |
| порядок (експонента) | 11 |
| мантиса | 52 |

Разом **64 біти = 8 байтів** на саме значення. Мантиса й порядок записані у двійковій системі, тому багато десяткових дробів зберігаються лише наближено (`0.1 + 0.2 = 0.30000000000000004`).

Сам Python-об'єкт `float` займає більше: у CPython на 64-бітній системі `sys.getsizeof(1.5)` дає **24 байти** (8 байтів лічильник посилань + 8 байтів вказівник на тип + 8 байтів саме число). Для порівняння, `int` змінної довжини: `sys.getsizeof(1)` = 28 байтів.

Код: [`code/float_size.py`](code/float_size.py)

```
Розмір самого значення (struct, формат 'd'): 8 байтів
Розмір Python-об'єкта float: 24 байтів
Біти 1.5: 0 01111111111 1000000000000000000000000000000000000000000000000000
0.1 + 0.2 = 0.30000000000000004
```

## 2. Округлення в JavaScript. Чи є інші мови з таким округленням?

**Python 3:** `round()` використовує *банківське округлення* (round half to even): якщо число рівно посередині, воно округлюється до найближчого **парного**. Тому `round(2.5) = 2`, а `round(3.5) = 4`.

**JavaScript:** `Math.round()` округлює «половинки» в бік **+∞** (round half up). Тому `Math.round(2.5) = 3`, `Math.round(3.5) = 4`, а для від'ємних `Math.round(-2.5) = -2` (до більшого, тобто до нуля), що відрізняється від «математичного» округлення від нуля.

Інші мови:
- **Схожі на JavaScript** (половинка вгору): Java `Math.round()`, Kotlin `roundToInt()`.
- **Половинка від нуля** (2.5 → 3, −2.5 → −3): Ruby `round`, Go `math.Round`, PHP `round`, Rust `f64::round`, Swift `rounded()`, Excel `ROUND`.
- **Банківське округлення, як у Python 3**: C# `Math.Round()` (за замовчуванням), R `round()`, Julia `round()`, NumPy `np.round()`, C `rint()`/`nearbyint()` (у стандартному режимі).

## 3. Математично-прийняте округлення в Python (2.5 і 3.5 вгору, 2.49 → 2)

Найнадійніше використовувати модуль `decimal` з режимом `ROUND_HALF_UP`:

```python
from decimal import Decimal, ROUND_HALF_UP

def round_half_up(x, digits=0):
    q = Decimal(1).scaleb(-digits)
    return Decimal(str(x)).quantize(q, rounding=ROUND_HALF_UP)

round_half_up(2.5)    # 3
round_half_up(3.5)    # 4
round_half_up(2.49)   # 2
```

`str(x)` береться для того, щоб працювати з десятковим записом числа, а не з його двійковим наближенням (`round(2.675, 2)` дає `2.67`, а `round_half_up(2.675, 2)` дає `2.68`). Для додатних чисел також підійде `math.floor(x + 0.5)`.

## 5. Скільки байтів у одній секунді кольорового відео (22 кадри/с)?

Розрахунок:

1. Кількість пікселів у кадрі = ширина × висота.
2. Кольоровий піксель RGB має 3 канали (R, G, B) по 1 байту (значення 0–255) = **3 байти**.
3. Байтів у кадрі = пікселі × 3.
4. Байтів за секунду = байтів у кадрі × 22.

**Для комп'ютера (1920 × 1080):**

- пікселів у кадрі: 2 073 600
- байтів у кадрі: 2 073 600 · 3 = **6 220 800**
- байтів за секунду: 6 220 800 · 22 = **136 857 600 байтів** ≈ 136,86 МБ (≈ 130,52 МіБ)

Розрахунок можна перевірити, змінивши `WIDTH`/`HEIGHT` у файлі [`code/video_memory.py`](code/video_memory.py). Це «сире» відео без стиснення; у реальних файлах (H.264 тощо) воно значно менше.

## 6. Як перетворити RGB у greyscale? Скільки пам'яті тоді потрібно?

Для чорно-білого зображення кожному пікселю потрібне одне значення яскравості замість трьох. Найпростіший спосіб — середнє: `(R + G + B) / 3`. Точніший, бо око по-різному сприймає колір — зважена сума (ITU-R BT.601):

```
Y = 0.299 · R + 0.587 · G + 0.114 · B
```

Приклад: піксель (200, 100, 50) → 0.299·200 + 0.587·100 + 0.114·50 ≈ **124** (середнє дало б 117).

Після цього піксель займає **1 байт** замість 3, тобто пам'яті потрібно в **3 рази менше**.

**Для комп'ютера (1920 × 1080, 22 кадри/с):** 2 073 600 · 1 · 22 = **45 619 200 байтів** ≈ 45,62 МБ (≈ 43,51 МіБ) за секунду.

## 7. Відео на половину ширини й половину висоти екрана

Ні, **не в 2 рази, а в 4**. Пам'ять залежить від площі (кількості пікселів = ширина × висота). Якщо ширина зменшується вдвічі й висота вдвічі, площа зменшується в 2 · 2 = **4 рази**.

**Для комп'ютера:** 960 × 540 = 518 400 пікселів (було 2 073 600); кольорове відео: 518 400 · 3 · 22 = **34 214 400 байтів** за секунду (було 136 857 600, тобто менше в 4 рази); чорно-біле: 11 404 800 байтів за секунду.
