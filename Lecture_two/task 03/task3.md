# Завдання 3. Кольорове зображення — три матриці

Код і графіки: `task3.ipynb` (у цій же папці).

## 1. Початковий прогноз

Перші чотири пікселі верхнього рядка: `[255,0,0]`, `[0,255,0]`, `[0,0,255]`, `[255,255,255]`.

**Прогноз:** червоний, зелений, синій, білий. Другий рядок: жовтий, блакитний, пурпуровий, чорний. Третій рядок: темно-синій, жовто-помаранчевий, сірий, світло-синій.

## 2. Зміна одного каналу

Піксель `row=2, col=0`, початково `[40, 80, 200]` (темно-синій).

| Канал | Нове значення | RGB до зміни | Прогноз | RGB після зміни | Що спостерігали |
|---|---|---|---|---|---|
| R | 0 | [40, 80, 200] | майже без змін, трохи синіший | [0, 80, 200] | ще синій, трохи холодніший |
| R | 128 | [40, 80, 200] | світліший, фіолетовіший відтінок | [128, 80, 200] | синьо-фіолетовий |
| R | 255 | [40, 80, 200] | помітно фіолетовий/пурпуровий | [255, 80, 200] | яскравий рожево-пурпуровий |
| G | 0 | [40, 80, 200] | темніший, насиченіший синій | [40, 0, 200] | насичений синій з фіолетовим відтінком |
| G | 128 | [40, 80, 200] | світліший, блакитніший | [40, 128, 200] | світліший синій з блакитним відтінком |
| G | 255 | [40, 80, 200] | блакитний | [40, 255, 200] | яскравий бірюзово-блакитний |
| B | 0 | [40, 80, 200] | зникає синя складова, темний колір | [40, 80, 0] | дуже темний оливковий |
| B | 128 | [40, 80, 200] | темніший, менш насичений синій | [40, 80, 128] | приглушений сіро-синій |
| B | 255 | [40, 80, 200] | трохи яскравіший синій | [40, 80, 255] | чистіший яскравий синій |

## 3. Канали та їх перестановка

**Прогноз світлих пікселів:** на R — (0, 0), R = 255; на G — (0, 1), G = 255; на B — (0, 2), B = 255.

Матриці каналів:

```
R:                    G:                    B:
[[255   0   0 255]    [[  0 255   0 255]    [[  0   0 255 255]
 [255   0 255   0]     [255 255   0   0]     [  0 255 255   0]
 [ 40 220 128  80]]    [ 80 160 128 120]]    [200  20 128 200]]
```

Форми каналів: `(3, 4)` для кожного.

**Перестановка R і B** (координати пікселів зберігаються):

| Піксель | RGB до | RGB після |
|---|---|---|
| (0, 0) | [255, 0, 0] | [0, 0, 255] |
| (2, 0) | [40, 80, 200] | [200, 80, 40] |

`np.array_equal(image, restored)` → `True`. Перестановка R↔B лише міняє місцями дві складові кожного пікселя й нічого не втрачає, тому повторна перестановка повертає кожну складову на місце.

## 4. Два способи перетворення на градації сірого

**Прогноз:** просте середнє для чистих R, G, B дасть однакове значення (255/3 = 85). Зважена сума дасть різні значення: найбільше для зеленого, потім червоний, найменше для синього.

| Піксель | Координати | RGB | Прогноз для середнього | Середнє, після округлення | Прогноз для зваженої суми | Зважена сума, після округлення |
|---|---|---|---|---|---|---|
| Чистий червоний | (0, 0) | [255, 0, 0] | 85 | 85 | ≈ 76 | 76 |
| Чистий зелений | (0, 1) | [0, 255, 0] | 85 | 85 | ≈ 150 | 150 |
| Чистий синій | (0, 2) | [0, 0, 255] | 85 | 85 | ≈ 29 | 29 |
| Сірий | (2, 2) | [128, 128, 128] | 128 | 128 | 128 | 128 |

### Ручні обчислення

- Червоний `[255, 0, 0]`: середнє = 255 / 3 = **85.0** → 85; зважена = 0.299 · 255 = **76.245** → 76.
- Зелений `[0, 255, 0]`: середнє = 255 / 3 = **85.0** → 85; зважена = 0.587 · 255 = **149.685** → 150.

Значення в масиві збігаються з округленими результатами.

### Сірий піксель (2, 2)

У нього R = G = B = 128. Середнє = 128. Зважена сума = 128 · (0.299 + 0.587 + 0.114) = 128 · 1 = 128. Коефіцієнти в сумі дають 1, тому для рівних каналів обидва способи дають те саме число. У чистих основних кольорів канали різні, тому способи розходяться.

## 5. Форма масивів і обсяг даних

| Зображення | shape | dtype | Кількість пікселів | size | nbytes, байтів |
|---|---|---|---|---|---|
| RGB | (3, 4, 3) | uint8 | 12 | 36 | 36 |
| Сіре: просте середнє | (3, 4) | uint8 | 12 | 12 | 12 |
| Сіре: зважена сума | (3, 4) | uint8 | 12 | 12 | 12 |

## 6. Відповіді на питання

1. `image[1, 2]` — повний RGB-вектор піксела в рядку 1, стовпці 2: `[255, 0, 255]` (пурпуровий). `image[1, 2, 0]` — одне число, значення каналу R цього піксела: `255`.
2. Ні. Виділення одного каналу бере лише одну складову, а решту двох ігнорує. Перетворення на сіре об'єднує всі три канали в одне число.
3. Перестановка R↔B лише міняє складові місцями, тому вона оборотна. Перетворення на сіре зводить три числа до одного й втрачає інформацію. Червоний `[255, 0, 0]`, зелений `[0, 255, 0]` і синій `[0, 0, 255]` дають для середнього те саме 85, тож за цим числом не можна відновити початковий колір.
4. Кількість пікселів не змінилася (12). Кількість числових елементів зменшилась з 36 до 12, а при однаковому `uint8` обсяг даних `nbytes` — з 36 до 12 байтів, тобто втричі.

## 7. Висновок

Кольорове зображення — це масив форми (висота, ширина, 3), тобто три матриці каналів R, G, B. Зміна однієї складової змінює колір піксела передбачувано: R додає червоного, G — зеленого, B — синього. Перестановка каналів оборотна, а перетворення на сіре ні, бо зводить три числа до одного. Просте середнє дає однакове сіре для чистих основних кольорів, а зважена сума враховує різний внесок каналів (зелений найсвітліший, синій найтемніший). Для сірих пікселів (R = G = B) обидва способи збігаються. Перехід до градацій сірого зменшує обсяг даних втричі за тієї самої кількості пікселів.
